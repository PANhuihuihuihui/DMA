<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser cookie → backend | Session token crosses into `resolve_session`; forged/expired/unknown tokens must be rejected and must never widen tenant scope |
| merchant A data ↔ merchant B data | All scheduled_posts / connected_channels queries must be scoped by the session-resolved merchant_id |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Spoofing | `sessions.resolve_session` | mitigate | Opaque token row lookup; reject missing/expired/logged_out; flip expired rows to `expired` (D-20) |
| T-05-02 | Information Disclosure | session token in logs/serializers | mitigate | `serialize_session` redacts the token; raw token never logged; `ip_hash` only, never raw IP |
| T-05-03 | Elevation of Privilege | cross-tenant data access | mitigate | resolve_session returns exactly one merchant_id; all new-table queries scoped by it (D-19) |
| T-05-04 | Tampering | premature publish via disconnected channel | mitigate | scheduled_post advance gate requires connected_channel.status == connected (D-21) |
</threat_model>
