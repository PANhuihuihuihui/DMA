<objective>
Split the OAuth callback so it stops silently auto-committing a Page: the callback fetches and returns the merchant's managed Pages, the merchant chooses one in a picker (UI in 04-08), and a dedicated select endpoint commits the chosen Page as the single active publish target and stores its encrypted token. Support connecting multiple Pages with one active, plus switch-active and reconnect.

Purpose: D-08 (callback returns Pages, no `choose_page()` auto-commit; second call commits + stores token), D-09 (multiple Pages, exactly one active), D-10 (in-scope management: select at connect, switch active, re-run OAuth to refresh). ACCT-01 (start connection) + ACCT-02 (select one Page). Full disconnect (ACCT-07) stays Phase 5.
Output: refactored `complete_callback`, new connect-session + select/switch logic, new server routes, and client functions.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Facebook OAuth redirect → backend callback | `state`/`code` from the browser cross here; CSRF/replay surface |
| client → select/switch endpoints | Merchant-supplied `connectSession`/`pageId` choose which Page gets committed |
| connect-session (in-memory) → backend | Holds per-Page tokens transiently before selection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Spoofing | `complete_callback` state handling | mitigate | Keep existing `pop_valid_state` (random state + TTL) for CSRF; connect-session id is a fresh `secrets.token_urlsafe` with TTL |
| T-04-04b | Tampering | `select_page(session_id, page_id)` | mitigate | Validate `page_id` belongs to the named session before committing; unknown → StoreError; never trust a raw token from the client |
| T-04-01 | Information Disclosure | session page list / `connection_status` | mitigate | Sanitize page lists to drop `access_token`; tokens persisted only via encrypted vault (04-03) |
| T-04-SC | Tampering | dependencies | accept | No new installs in this plan |
</threat_model>
