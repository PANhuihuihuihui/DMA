Existing seams: `queue_facebook_publish` already creates jobs/attempts/events, calls `publish_approved_snapshot`, on success calls `store.record_publish_outcome(conn, job_id, attempt_id, snapshot, provider="facebook", provider_result_ref=provider_ref)`, and sets terminal status (`published` | `failed` | `retry_needed`). `classify_error_class(status, provider_error)` returns auth/missing_permission/validation/rate_limit/platform_transient/unknown. `provider_diagnostics(error_class, result, extra)` sets `nextRecommendedAction`. The generic retry route today is `POST /api/v1/publish-jobs/:id/retry` → `fake_publisher.retry_fake_publish(...)`. Publish jobs carry a `provider`/`platform`. Idempotency: jobs are created from the approved snapshot with an idempotency key (Phase 1) and `create_publish_job` returns an already-`published` job without re-posting.

Recovery-action mapping (FB-06):
- authentication / 190 → `reconnect` (already flips reconnect_required in 04-05)
- missing_permission / page_capability → `reconnect` (re-grant permission) 
- rate_limit / platform_transient → `retry`
- validation → `fix_media_or_copy` (no retry without edit)
- unknown / repeated failure → `manual_fallback`
</context>
