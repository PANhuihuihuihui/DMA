### Reference implementation to port from (do not reinvent)

The AiToEarn reference repo already ships a proven Google ID-token login. Port its verification + identity-resolution logic, adapting it from NestJS/MongoDB to LocalPilot's Python/SQLite seams and to httpOnly-cookie sessions (AiToEarn returns a JWT to the browser — we must NOT; keep LocalPilot's cookie transport).

- `/tmp/AiToEarn/project/aitoearn-electron/server/src/modules/plat/google/google.service.ts` — `googleLogin(clientId, credential)`: `oauth2Client.verifyIdToken({ idToken, audience })`, then `sub` lookup → email fallback → create user. This maps almost 1:1 onto `verify_google_id_token` + `resolve_or_create_identity` below.
- `/tmp/AiToEarn/project/aitoearn-electron/server/src/modules/plat/google/dto/google.dto.ts` — `GoogleLoginDto { clientId, credential }` is the request shape; LocalPilot accepts the same `credential` field (clientId is server-owned via `GOOGLE_CLIENT_ID`).
- `/tmp/AiToEarn/project/aitoearn-web/src/api/auth/auth.types.ts` — `GoogleLoginParams { clientId, credential }` confirms the client/backend contract.

Differences to enforce (LocalPilot, not AiToEarn): httpOnly + Secure + SameSite cookie instead of a JS-held token; `sub` + verified-email linking under one-user-one-merchant; `google-auth` Python lib instead of Node `google-auth-library`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser credential → backend | The Google credential must be verified server-side; never trust client-sent identity |
| backend session → browser | Session token must be httpOnly/Secure and never readable by JS or stored in localStorage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01-01 | Spoofing | Google credential | mitigate | Verify signature, `aud`==client ID, `iss`, `exp` via google-auth; reject otherwise |
| T-07-01-02 | Information Disclosure | session token | mitigate | Deliver via httpOnly+Secure+SameSite cookie; never echo token in JSON or logs |
| T-07-01-03 | Elevation of Privilege | dev bypass | mitigate | Gate dev login behind LOCALPILOT_DEV_LOGIN and disable it whenever GOOGLE_CLIENT_ID is set |
| T-07-01-04 | Tampering | identity linking | mitigate | Link by verified email only; use `sub` as the durable key; unique index on google_sub |
</threat_model>
