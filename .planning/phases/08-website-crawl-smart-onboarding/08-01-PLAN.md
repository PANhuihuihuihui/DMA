<objective>
Add the backend crawl-and-extract pipeline for website-based smart onboarding. A merchant submits a URL → the backend fetches the homepage, cleans the HTML, sends it to the LLM for structured brand extraction, and stores the result as a draft merchant profile. The merchant can then read, edit, and confirm the profile through REST endpoints. Satisfies ONBOARD-01, ONBOARD-02, ONBOARD-03, and ONBOARD-05.

Output: a `website_crawl` module (fetch, clean, extract), a `merchant_profiles` table with store helpers, four onboarding API routes, and tests with mocked HTTP + LLM.
</objective>

  <action>
  Create `backend/app/website_crawl.py` with three public functions:

  **`fetch_homepage(url)`**
  - Validate the URL (must start with `http://` or `https://`, reject empty/invalid).
  - Use `urllib.request.urlopen` with a `Request` setting `User-Agent: LocalPilotBot/1.0 (+https://localpilot.ai)` and a 12-second timeout.
  - Read up to 2 MB of response body; decode as UTF-8 (with fallback to latin-1).
  - Return the HTML string.
  - On any error (timeout, DNS, HTTP 4xx/5xx, SSL), raise a `CrawlError(message, partial=None)` that carries a user-friendly message.

  **`clean_html_for_llm(html)`**
  - Extract useful meta tags: `<title>`, `<meta name="description">`, `<meta property="og:*">`, `<meta name="theme-color">`, any `<script type="application/ld+json">` blocks.
  - Strip `<script>`, `<style>`, `<nav>`, `<header>`, `<footer>`, `<noscript>`, `<iframe>` elements and their contents.
  - Extract remaining visible text from the body, collapsing whitespace.
  - Assemble into a structured text block: meta section + body text.
  - Truncate to approximately 8,000 tokens (~32,000 characters as a conservative estimate).
  - Return the cleaned text string.

  **`extract_brand_profile(cleaned_text, *, api_key=None)`**
  - Build a chat completions request to `https://api.minimax.io/v1/chat/completions` using model `MiniMax-M3`.
  - System prompt instructs the model to extract brand profile data from the provided website text and return a JSON object with exactly these keys: `name`, `description`, `industry`, `logo_url`, `primary_color`, `secondary_color`, `accent_color`, `font_family`, `language`, `timezone`, `tonality`, `target_audience`.
  - Use `response_format: {"type": "json_object"}` to ensure JSON output (MiniMax supports this in OpenAI-compatible mode).
  - Parse the response JSON; validate each field is a string; sanitize all values (strip HTML tags, validate color hex format, validate URL format for logo_url).
  - On LLM failure or parse error, return a partial profile dict with empty strings for missing fields (D-14/D-15 — never block).
  - Use `MINIMAX_API_KEY` from env. The MiniMax API is OpenAI-compatible — same Authorization: Bearer header, same request/response schema.

  **`CrawlError`** — exception class with `message` and optional `partial` dict.

  All string outputs must be sanitized per D-16: `html.escape` text fields, URL validation for `logo_url`, hex validation for colors.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| merchant URL → backend fetch | The URL comes from user input; must validate scheme, apply timeout, and limit response size |
| external HTML → LLM prompt | Crawled HTML may contain malicious content; must be cleaned before LLM and before storage |
| LLM response → database/UI | LLM output may echo injected content from the crawled page; must sanitize all fields |
| browser → onboarding API | All onboarding routes require authenticated merchant session (Phase 7 auth) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01-01 | Tampering | URL input | mitigate | Validate URL scheme (http/https only), reject file://, localhost, private IPs; apply timeout and size limit |
| T-08-01-02 | Information Disclosure | crawl fetch | mitigate | User-Agent identifies the bot; respect robots.txt; do not expose raw HTML or full LLM prompts in API responses |
| T-08-01-03 | Tampering | LLM output | mitigate | Sanitize all extracted fields: html.escape text, validate hex colors, validate URLs; store sanitized values only |
| T-08-01-04 | Denial of Service | large pages | mitigate | Limit fetch to 2 MB response body; truncate cleaned text to ~8K tokens before LLM; 12s fetch timeout |
| T-08-01-05 | Spoofing | unauthenticated access | mitigate | All onboarding routes resolve merchant_id from authenticated session; no anonymous crawl |
| T-08-01-06 | Information Disclosure | raw_extraction_json | accept | Raw LLM JSON stored for debugging; not exposed in API responses (serialize_merchant_profile excludes it) |
</threat_model>
