# 03-02 Plan: Predis Logged-In Reference Clone Hardening

## GSD Entry

Use `/gsd-execute-phase` for this work. This is not a small cosmetic quick task: it changes the Phase 3 target from public Predis parity to logged-in Predis workflow parity based on the reference screenshots in `reference/`.

## Goal

Make LocalPilot's Phase 3 workspace feel like the logged-in Predis.ai product flow in the reference screenshots, while keeping LocalPilot's differentiator: local-business strategy, explicit owner approval, official/OAuth publishing boundaries, and proof-loop evidence.

Important boundary: clone the feature workflow, layout patterns, and parity surface. Do not copy Predis trademarks, exact creative assets, private implementation, or copyrighted template art. LocalPilot should look recognizably comparable, not literally impersonate Predis.

## Why The Overall Plan Should Change

The existing Phase 3 plan is broadly correct, but the screenshots show Predis is more workflow-specific than our current nine-screen map. The plan should be tightened from “generic Predis-style screens” to these logged-in product moments:

1. Left-nav app shell with persistent create button, trial/account panel, and help entry.
2. Inspirations-first discovery surface with category tabs and video/image/card grids.
3. Content Library as the central asset list, with type filters, date/tags/users/source filters, archive toggle, watermark status, and publish entry.
4. Content Calendar with weekly/monthly toggle, timezone selector, status legend, and scheduled-post details drawer.
5. Brand & Social Accounts split into Social Platforms, Brand Details, Integrations, and Exports tabs.
6. Official Meta OAuth modal and page-selection modal for Facebook connection.
7. Analytics dashboard with posting streak, consistency grid, account metrics, posting activity, engagement, and follower growth empty states.
8. Create New chooser for Image, UGC, Short Ad Video, Carousel, Faceless Video, and Product Photo Shoot.
9. Per-format creation methods: write idea, product/store import, product URL, and image upload.
10. Carousel configuration before generation: style presets, aspect ratio, and brand settings confirmation.
11. Publish/schedule modal from content library, with unsupported-media warnings and missing-account linking prompts.
12. Auto-posting upsell after scheduling, but LocalPilot should convert this into “weekly local autoplan after owner approval,” not autonomous publishing.

Therefore Phase 3 should be treated as still active but needing a 03-02 parity-hardening plan before moving to Phase 4 hardening.

## Product Decision

Keep the roadmap order, but insert this as Phase 3.2 before Phase 4:

- Phase 3.1: already implemented broad Predis-style demo surface and LocalPilot proof loop.
- Phase 3.2: logged-in Predis reference clone hardening from screenshots. This makes the demo visually and behaviorally credible.
- Phase 4: Facebook Page Publishing Hardening remains next after the demo surface is tight.

Do not move TikTok production direct-post work earlier. TikTok remains assisted in Phase 3 and official in Phase 5.

## Risks And Guardrails

- Risk: “exact clone” could become IP/trademark copying. Guardrail: clone workflow parity and layout conventions, not Predis marks/assets/copy.
- Risk: too many UI surfaces in one `src/main.jsx`. Guardrail: keep changes organized with data arrays and small render helpers; consider extraction only if file becomes unmanageable.
- Risk: adding placeholders weakens product focus. Guardrail: mark unsupported channels/integrations as assisted/planned and keep Facebook-first production path.
- Risk: account connection UI could imply tokens are client-side. Guardrail: explicit copy says credentials stay server-side; storage-boundary smoke remains required.
- Risk: auto-posting copy conflicts with owner approval. Guardrail: LocalPilot’s version is owner-approved weekly autoplan, not autonomous publishing.
