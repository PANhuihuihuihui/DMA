<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> `/api/v1/generation/jobs` | Untrusted launch payload can try to bypass the fixed preset, brand lock, or ledger rules. |
| backend -> MiniMax API | Server-side provider call carries API keys and generated prompts that must stay off the client. |
| backend -> SQLite store | Job, creative, media-asset, and credit-ledger writes must remain atomic and merchant-scoped. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01-01 | Tampering | `store.create_generation_job` | mitigate | Validate `workflowType`, fixed `slideRoles`, fixed `4:5`, and brand-kit presence server-side; ignore any client-supplied brand styling or credit values. |
| T-11-01-02 | Information Disclosure | `backend/app/generation_providers/minimax_adapter.py` | mitigate | Keep `MINIMAX_API_KEY` server-side and serialize provider failures only through `ProviderError` plus `safe_diagnostics`. |
| T-11-01-03 | Tampering | `generation_dispatch.dispatch_generation_job` + `credit_ledger` | mitigate | Keep one admission transaction, one reservation, one settle/release path, and one materialized creative package per parent job. |
| T-11-01-SC | Tampering | npm/pip/cargo installs | accept | No new package-manager installs are planned; reuse stdlib HTTP plus current repo dependencies only. |
</threat_model>
